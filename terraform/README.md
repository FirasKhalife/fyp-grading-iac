# Terraform / OpenTofu version

A reference deployment of the FYP grading platform on AWS, written in OpenTofu/Terraform.

> See also the [root README](../README.md) and the [CDK version](../cdk). **This stack is validated but never applied.** Nothing in this repo has created a resource in a real AWS account, and CI has no AWS credentials. It exists to show how the platform *would* be hosted on AWS. The live demo runs somewhere else, see [Why the live demo is not on AWS](#why-the-live-demo-is-not-on-aws).

## What it deploys

```
                 Internet
                    |
            [Internet Gateway]
                    |
   public subnets (2 AZs)  -- NAT gateway (one, shared)
                    |
   private subnets (2 AZs)
        |
   one EC2 instance (t3.xlarge, Amazon Linux 2023)
        - Docker Compose runs the whole platform:
          7 Spring Boot services, Keycloak, Postgres, Mongo, RabbitMQ, Redis
        - no public IP, no inbound rules at all
        - reached only through SSM Session Manager
```

| Piece | What it does |
|---|---|
| `modules/vpc` | VPC `/16`, public and private `/20` subnets in 2-3 AZs, internet gateway, one optional NAT gateway, route tables, locked-down default security group, flow logs to an encrypted CloudWatch log group |
| Instance | One `t3.xlarge` (4 vCPU, 16 GiB) in a private subnet. A single instance is deliberate: the platform is a demo, and the full stack needs roughly 10-12 GiB, so splitting it over many small hosts costs more and fails more (the old config packed two JVMs and Postgres on a 1 GiB `t2.micro`). |
| Access | SSM Session Manager instead of SSH: no key pair, no port 22, no bastion. The instance role has `AmazonSSMManagedInstanceCore` and nothing else beyond reading its own secrets. |
| Instance hardening | IMDSv2 required, metadata hop limit 1 (containers cannot reach the metadata service), encrypted gp3 root volume, detailed monitoring, EBS optimized, security group with **no inbound** and HTTPS-only outbound |
| Secrets | Four passwords (Postgres, Mongo, RabbitMQ, Keycloak admin) are generated by `random_password` and stored as SSM Parameter Store `SecureString` values under `/fyp-grading/<env>/`, encrypted with a customer-managed KMS key (rotation on). The boot script reads them with the instance role at startup, so `user_data` contains no secrets. |
| AMI | Resolved from the public SSM parameter `/aws/service/ami-amazon-linux-latest/al2023-ami-kernel-default-x86_64`, never hardcoded. `ignore_changes = [ami]` stops a new AMI release from silently replacing the host. |
| State | S3 backend with native locking (`use_lockfile`, no DynamoDB). `bootstrap/` holds the small stack that would create the bucket (versioned, encrypted, public access blocked, TLS only). |

How you would reach it: `tofu output ssm_port_forward_command` prints an `aws ssm start-session` command that forwards the API gateway to `localhost:8080`. Public ingress (an ALB with a certificate and WAF) is intentionally **not** included, see the cost section.

## Estimated monthly cost

Rough on-demand prices for `us-east-1`, 730 hours per month. These are my estimates from published list prices, not an `infracost` run, so check them before relying on them.

| Item | $/month |
|---|---|
| `t3.xlarge` instance (~$0.166/h) | ~121 |
| NAT gateway (~$0.045/h) plus ~50 GB of traffic | ~35 |
| NAT public IPv4 address | ~4 |
| 60 GB gp3 volume | ~5 |
| Detailed monitoring, KMS key, flow logs, log storage | ~5 |
| **Total** | **~$170** |

Add roughly $18 plus traffic for an ALB if you wanted public ingress, and more for managed databases or Keycloak on separate hosts. Setting `enable_nat_gateway = false` saves ~$39 but the instance then has no way to pull images or packages unless you add VPC endpoints.

## Why the live demo is not on AWS

A grading demo that a recruiter clicks a few times a month does not need $170/month of infrastructure. The live demo runs on a single Netcup VPS behind a Cloudflare Tunnel, which has a flat, much lower monthly price, no NAT or load balancer charges, and no open inbound ports (the tunnel dials out). The services, Docker Compose file and images are the same ones this repo deploys, so this repo answers "how would you run it on AWS?" while the VPS answers "where can I click it?".

## Layout

| Path | Purpose |
|---|---|
| `versions.tf`, `providers.tf`, `backend.tf` | OpenTofu >= 1.9, AWS provider `~> 6.0`, S3 backend (partial config) |
| `variables.tf`, `locals.tf`, `outputs.tf` | Inputs (with validation), naming, outputs |
| `main.tf` | KMS key, secrets, IAM, security group, instance |
| `templates/user_data.sh.tftpl` | Boot script: Docker, clone the compose repo, fetch secrets from SSM, start a systemd unit |
| `modules/vpc` | Network module |
| `bootstrap/` | State bucket stack (validated, never applied) |
| `tests/` | `tofu test` suites using mocked providers |
| `.tflint.hcl` | Lint config (CI is in `../.github/workflows/ci.yml`) |

## Checks (no AWS account or credentials needed)

```bash
tofu fmt -check -recursive
tofu init -backend=false && tofu validate
(cd bootstrap && tofu init -backend=false && tofu validate)
tofu test                      # 9 plan-level assertions against a mocked AWS provider
tflint --init && tflint --recursive
checkov -d . --framework terraform
```

All of these pass. Eight checkov findings are skipped inline, each with a reason: KMS key-policy `Resource "*"` (it means "this key"), and four S3 hardening extras on the state bucket (replication, access logging, event notifications, KMS instead of SSE-S3) that are overkill for a demo.

The mocked tests assert what matters for safety: IMDSv2 required, encrypted root volume, no public IP, no inbound rules, HTTPS-only egress, all secrets are `SecureString`, `user_data` embeds no secret, and bad instance sizes or environment names are rejected.

## If you ever did want to apply it

Don't do this casually: it costs money. You would run `bootstrap/` once, copy `backend.hcl.example` to `backend.hcl` with the bucket name, then `tofu init -backend-config=backend.hcl`, `tofu plan`, `tofu apply`. State will contain the generated passwords, which is why the bucket is encrypted and private.

## Known limits

- One instance and one NAT gateway: no high availability.
- No public ingress, DNS or TLS. Access is by SSM port forwarding.
- Postgres, Mongo, RabbitMQ and Redis run in containers on the instance volume, not as managed services, and there is no backup job.
- The boot script has not been run on a real instance. It is plausible but untested.
